You build a small routed application in this tutorial: a root layout, an index page, a user detail page with a loader, and typed navigation between them. The same route table you create here runs on GPUI, Dioxus, Leptos, Xilem, and Floem — only the three-line host bootstrap differs.

## Prerequisites

- [Rust](https://rustup.rs) 1.85 or newer (Navi uses edition 2024).
- A working GPUI toolchain for your platform if you follow the GPUI host step.
- A clone of the [navi workspace](https://github.com/elcoosp/navi) next to your project, because the quoin and rs-query crates it builds on are consumed as local path dependencies (see [Installation](/guides/installation/)).

## 1. Add the dependencies

Add the Navi crates plus quoin with your framework's feature to `Cargo.toml`:

<Code lang="toml" title="Cargo.toml" code={"[dependencies]\nnavi-router = { path = \"../navi/navi-router\" }\nnavi-macros = { path = \"../navi/navi-macros\" }\nquoin      = { path = \"../quoin/quoin\", features = [\"gpui\"] }"} />

The `features` value selects your UI framework: `gpui`, `dioxus`, `leptos`, `xilem`, or `floem`. Everything else in this tutorial stays identical across the five.

## 2. Create the route files

Routes are plain Rust files under `src/routes`. Create a root layout at `src/routes/__root.rs` — files named `__root` or starting with `_` become layouts that render their children through an `<Outlet>`:

<Code lang="rust" title="src/routes/__root.rs" code={"use navi_macros::define_route;\nuse navi_router::components::{Link, Outlet};\nuse quoin_ui::{Node, StyleCmd};\n\nfn root_node() -> Node {\n    Node::div()\n                    .styles([StyleCmd::FlexCol])\n                    .child(Link::new(\"/\").child(\"Home\").build())\n                    .child(Outlet::new().build())\n                    .build()\n}\n\ndefine_route!(RootRoute, path: \"/\", is_layout: true, node: root_node);"} />

Create the index page at `src/routes/index.rs`:

<Code lang="rust" title="src/routes/index.rs" code={"use navi_macros::define_route;\nuse navi_router::components::Link;\nuse quoin_ui::{Node, StyleCmd};\n\nfn index_node() -> Node {\n    Node::div()\n                    .styles([StyleCmd::FlexCol, StyleCmd::Gap(6.0), StyleCmd::Padding(12.0)])\n                    .child(Node::text(\"Welcome!\"))\n                    .child(Link::new(\"/users/42\").child(\"Open /users/42\").build())\n                    .build()\n}\n\ndefine_route!(IndexRoute, path: \"/\", is_index: true, node: index_node);"} />

Add the dynamic user route at `src/routes/users/$id.rs`. The `$id` file name declares a path parameter, and the `loader` runs when someone navigates to the route:

<Code lang="rust" title="src/routes/users/$id.rs" code={"use std::sync::Arc;\n\nuse navi_macros::{define_route, use_loader_data};\nuse serde::{Deserialize, Serialize};\n\n#[derive(Clone, Debug, Deserialize, Serialize)]\npub struct UserParams {\n    pub id: String,\n}\n\n#[derive(Clone, Debug, PartialEq)]\npub struct UserData {\n    pub id: String,\n    pub name: String,\n    pub email: String,\n}\n\ndefine_route!(\n    UsersParamIdRoute,\n    path: \"/users/$id\",\n    params: UserParams,\n    data: UserData,\n    loader: |params: UserParams| async move {\n                    let id = params.id;\n                    navi_router::sleep(std::time::Duration::from_millis(800)).await;\n                    Ok::<_, Box<dyn std::error::Error + Send + Sync>>(Arc::new(UserData {\n                                    id: id.clone(),\n                                    name: format!(\"User {id}\"),\n                                    email: format!(\"user{id}@example.com\"),\n                    }))\n    },\n    node: user_node,\n);\n\nfn user_node() -> Node {\n    // Reads the data the loader returned for this route.\n    let data = use_loader_data!(UsersParamIdRoute);\n    match data.map(|d| (*d).clone()) {\n                    Some(user) => Node::text(format!(\"{} \u2014 {}\", user.name, user.email)),\n                    None => Node::text(\"Loading...\"),\n    }\n}"} />

## 3. Configure code generation

Navi generates the route tree from your `src/routes` directory at build time. Create `navi.config.json` in your project root:

<Code lang="json" title="navi.config.json" code={"{\n  \"routes_directory\": \"./src/routes\",\n  \"generated_route_tree\": \"./src/route_tree.gen.rs\",\n  \"route_token\": \"route\",\n  \"index_token\": \"index\",\n  \"route_file_ignore_prefix\": \"-\"\n}"} />

Then wire the generator into `build.rs`:

<Code lang="rust" title="build.rs" code={"fn main() {\n    let config = navi_codegen::NaviConfig::from_file(\"navi.config.json\")\n                    .expect(\"Failed to read config\");\n    navi_codegen::generator::write_route_tree(&config).unwrap();\n}"} />

Every build now regenerates `src/route_tree.gen.rs`, which exposes `build_route_tree()` and `register_routes()`.

## 4. Boot the app

On GPUI, Xilem, and Floem you boot through quoin's `run_app!` host macro. Initialize the router inside your host with the generated tree:

<Code lang="rust" title="src/route_tree.gen.rs" code={"use navi_router::{Location, NotFoundMode, RouterOptions, RouterProvider};\n\nmod route_tree {\n    include!(\"route_tree.gen.rs\");\n}\n\nlet tree = route_tree::build_route_tree();\nlet router = RouterProvider::new_with_options(\n    window_id,\n    window_handle,\n    Location::new(\"/\"),\n    tree,\n    RouterOptions {\n                    not_found_mode: NotFoundMode::Fuzzy,\n                    ..Default::default()\n    },\n    cx,\n);\nroute_tree::register_routes(cx);"} />

For the other frameworks only the bootstrap changes — the route table, loaders, guards, and devtools do not:

<Code lang="rust" code={"// Dioxus desktop\nfn app() -> Element { rsx! { NaviDemo {} } }\nfn main() { dioxus::LaunchBuilder::desktop().launch(app); }"} />

<Code lang="rust" title="src/lib.rs" code={"// Leptos CSR (wasm32)\n#[wasm_bindgen(start)]\npub fn main() {\n    leptos::mount::mount_to_body(|| view! { <NaviDemo /> });\n}"} />

## 5. Run it

<Code lang="bash" title="Terminal" code={"cargo run"} />

You start on `/`, follow the link to `/users/42`, and watch the loader resolve into rendered user data. Static segments always win over dynamic ones during matching, so adding `src/routes/users/new.rs` later shadows `$id` for that exact path deterministically.
