In Rust desktop and WASM applications, routing is often an afterthought: a global `Route` enum, a giant `match` block, and manual async fetching inside component mount hooks. When you switch UI toolkits, you throw the whole navigation layer away.

Navi brings TanStack Router semantics—file-based route trees, loaders, guards, and devtools—to Rust without coupling the router to a single UI crate.

## The Goal

We wanted build-time route generation from `src/routes`, typed path and query parameters, `before_load` redirects, and scroll restoration, all running unmodified across GPUI, Dioxus, Leptos, Xilem, and Floem.

## The Architecture

`navi-router-core` contains zero UI dependencies and no hardcoded async runtime. It matches URLs against a ranked radix trie using interned `Arc<str>` segments and stack-collected parameter bindings, delegating reactive state and rendering to `quoin`.

## What it cost

Keeping the core framework-free meant enforcing strict workspace rules: `#![forbid(unsafe_code)]`, pedantic Clippy lints with zero `#[allow]` suppressions, and maintaining five separate host demos (`demo-gpui`, `demo-dioxus`, `demo-floem`, `demo-xilem`, `demo-leptos`) over one shared `demo-core` crate.

<Aside type="caution" title="The Trade-off">
Portable routes render as `quoin_ui::Node` trees or `component!` blocks so they compile across all five backends. If you need direct access to raw GPUI-specific elements, you have to step out of the portable abstraction using `quoin`'s `rsx!` escape hatch.
</Aside>

## Getting started

```bash
cargo run -p navi-demo-gpui
```

Read the [getting started tutorial](/tutorials/getting-started/) to configure `navi.config.json` and define your first route.
